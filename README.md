# ARCH MAKERS — сайт (future-arch.md)

Next.js 16 + Payload CMS 3 на Postgres (Neon). Бывший Future Architecture.
Дизайн ARCH MAKERS 2026 перенесён из макетов Claude Design (`*.dc.html`) в React-компоненты;
весь текст редактируется из админки на трёх языках.

## Редизайн ARCH MAKERS (сентябрь 2026) — что где

- Страницы: `src/components/CommunityPage.tsx`, `ForumPage.tsx`, `AwardPage.tsx`, `PrivacyPage.tsx`,
  `NotFoundPage.tsx`; общие шапка, подвал и поля форм — `src/components/am/ui.tsx`.
- Разметка и инлайновые стили — из макетов дословно. Сетки, наведение и брейкпоинты
  (≥1100 десктоп, 720–1099 планшет, <720 телефон) — классы `am-*`, `hv-*`, `fc-*` в `globals.css`.
- Тексты: `src/i18n/ru.ts` (по умолчанию), `ro.ts`, `en.ts` — ключи `c*` общие, `h*` главная,
  `f*` форум, `a*` премия. Поля админки описаны в `src/cms/{common,home,forum,award}.ts`,
  сборка раздела — `src/cms/build.ts` (`l3` — поле на трёх языках).
- Спикеры — «Форум 2026 → Дата и спикеры». Портреты из макета встроены и подбираются по фамилии
  (`src/components/am/speakers.ts`); свой портрет из админки имеет приоритет.
- Номинации — «Премия и конкурсы → Приём заявок»: «Раздел» (Архитектура / Интерьер) + «Название».
- Файлы в заявках премии — приватное хранилище Vercel Blob `arch-makers-files`
  (`src/app/(payload)/api/attach/route.ts`): браузер грузит файл напрямую (до 20 МБ,
  pdf/jpg/png/zip), в заявке остаётся ссылка, которая открывается только после входа в админку.
- Шрифты: Onest (в `public/fonts`). **Actay Wide** лицензионный — положить
  `public/fonts/ActayWide-Bold.woff2`, до этого заголовки набираются Onest.
- Миграции `20260927_*` и `20260928_*` только добавляют: старые таблицы (`content_*`, `page_*`,
  `forum_settings`, `award_settings`, `seo`, `mail`, `analytics`) оставлены, чтобы откат был безопасным.

| Маршрут  | Страница        |
| -------- | --------------- |
| `/`      | Сообщество      |
| `/forum` | Форум 2026      |
| `/award` | Премия          |
| `/privacy` | Политика данных |

Языки: русский на корне, `/ro` и `/en` — своими ветками. В админке язык
переключается селектором локали вверху справа.

## Запуск локально

```bash
npm install
cp env.example.txt .env      # и подставить свои значения
npm run dev
```

Первый заход на `/admin` предложит создать администратора.

## Админка (future-arch.md/admin)

Устроена как «Страницы» в WordPress: одна страница сайта — один раздел со всем её содержимым.
Переключателя языков нет — у каждого текста три поля рядом: **RU · RO · EN**.
Поля заполнены текстом, который сейчас на сайте. Очистить поле = вернуть текст по умолчанию из кода.

| Раздел | Что внутри |
| --- | --- |
| Заявки — Сообщество / Форум / Премия | входящие заявки, статус, заметка |
| Страницы → Главная | все тексты главной |
| Страницы → Форум 2026 | дата и таймер, спикеры (фото, имя, строка под именем), тексты |
| Страницы → Премия и конкурсы | дедлайн, «приём открыт», номинации, тексты |
| Страницы → Меню, подвал и формы | пункты меню, контакты, соцсети, подписи форм |
| Настройки → Настройки сайта | куда приходят заявки и автоответ, SEO, счётчики |
| Файлы и доступ | фото и картинки, пользователи админки |

- Сохранение сразу сбрасывает кэш всех страниц (`revalidateSite` в `src/globals/pages.ts`) — правка видна через пару секунд.
- «Живой просмотр» (иконка глаза) показывает страницу рядом с формой; после сохранения она обновляется
  сама (`src/components/LivePreview.tsx` + `/api/site-version`).
- Фото из админки хранятся в публичном Vercel Blob `arch-makers-media` (`MEDIA_READ_WRITE_TOKEN`).
- Первый экран админки — `src/components/admin/Welcome.tsx`: новые заявки и ссылки на страницы.

## Как устроен перенос текста в CMS

Исходные страницы приехали бандлом, где все строки лежат под ключами `k1…k498`
(`src/i18n/ru.ts`, `ro.ts`, `en.ts`). Чтобы не переписывать 4500 строк вёрстки,
сделан слой описания:

- `src/cms/*.ts` — описание страницы: секции, поля, подписи и ключ словаря,
  который поле перекрывает.
- `src/cms/build.ts` — из одного описания собирает и глобал Payload
  (`buildGlobal`), и функцию наложения значений (`applyContent`).
- `src/lib/content.ts` — отдаёт компоненту словарь: код + то, что задано в админке.

Поэтому админка и вёрстка не могут разъехаться: добавили поле в описание —
оно появилось и в админке, и на сайте.

## Микротипографика

`src/i18n/typo.ts` прогоняет все строки — и из кода, и из админки:

- короткие предлоги и союзы приклеиваются к следующему слову неразрывным
  пробелом, чтобы строка не заканчивалась на «в», «и», «по»;
- числа приклеиваются к единице: «250 участников», «9 декабря»;
- дефис между словами становится тире и не уезжает на новую строку.

Редактору ничего специально ставить не нужно — достаточно писать обычным текстом.

## Миграции

Схема базы описана миграциями в `src/migrations`. Сборка (`npm run build`)
сначала прогоняет `payload migrate`, потом собирает Next.

Новая миграция после правки коллекций или глобалов:

```bash
npm run migrate:create
```

## Переменные окружения

См. `env.example.txt`. Обязательны только `DATABASE_URI`, `PAYLOAD_SECRET`
и `NEXT_PUBLIC_SITE_URL`.

## Как устроен перенос вёрстки

- **Разметка и инлайн-стили** перенесены дословно.
- **Адаптивность** раньше считалась в JavaScript — стала CSS-переменными с
  медиазапросами (`globals.css`). Значения на каждом брейкпоинте те же, но
  вёрстка больше не зависит от JS.
- **`style-hover` / `style-focus`** превратились в обычные CSS-классы.
- **Анимации** (`fa-motion.js`) — исходный ванильный скрипт без изменений:
  reveal по скроллу, счётчики, бегущие строки, таймеры, параллакс.
- **Состояние страниц** (меню, валидация форм, выбор трека премии) переписано
  на React-хуки один в один с исходной логикой.
